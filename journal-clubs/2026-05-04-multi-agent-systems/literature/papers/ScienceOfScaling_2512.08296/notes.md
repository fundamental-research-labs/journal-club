# Notes

This paper matters because it gives coding agents a practical vocabulary for deciding when to use single-agent, centralized, decentralized, independent, or hybrid agent systems.

Use it when arguing against "more agents always help," when selecting an agent architecture for a benchmark or product workflow, or when explaining why decomposable analysis tasks may benefit from coordination while sequential tool/planning tasks may degrade.

Key terms: single-agent system, multi-agent system, coordination overhead, capability saturation, architecture-task alignment, decomposability, tool complexity, error amplification.
