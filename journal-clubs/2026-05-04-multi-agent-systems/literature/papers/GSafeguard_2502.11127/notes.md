# Notes

## Why It Matters
G-Safeguard is useful because it treats multi-agent communication itself as a security surface. The paper's main contribution is not a new prompt filter, but a topology-aware view: agents can become infected by neighboring agents, and defense can operate by detecting risky nodes and cutting risky information flow.

## When To Cite
Cite this paper for topology-aware LLM-MAS security, GNN-based attacker or infected-agent detection, utterance-graph representations of agent communication, edge-pruning remediation, and empirical defenses against prompt injection, tool attack, or memory poisoning in multi-agent systems. It is also relevant when arguing that single-agent guardrails are incomplete for multi-agent pipelines.

## Key Terms
G-Safeguard; LLM-based multi-agent systems; multi-agent utterance graph; topology-aware defense; graph-based attack detection; edge-aware GNN; edge pruning; attack remediation; attack success rate; prompt injection; tool attack; memory poisoning; PoisonRAG; InjecAgent; CAMEL.
