\section{Related Work}
\label{sec:related_work}

\paragraph{Quality degradation under multi-turn coding.} LLM-generated code degrades under repeated modification. Code converges toward structural attractors~\citep{iterative-readability}, quality diverges across trajectories~\citep{chen2025-patch-quality, santos2025-software-aging}, and refinement introduces defects that correctness testing does not catch~\citep{scaffold-cegis, diff-fuzzing-refactoring, bohr2025-show-and-tell}. Interaction failure modes compound these effects~\citep{interaction-smells, overcorrection-reviewers, more-rounds-more-noise}; agent-generated bloat is already a practical barrier to integration~\citep{what-to-cut, nakashima2026-agentic-prs, vibe-coding-overhead}. No existing work tracks verbosity or structural erosion over time.

\paragraph{Code quality metrics.} Code smells are well-studied in software engineering~\citep{fowler1999-refactoring, lacerda2020-code-smells-tertiary}. \citet{abbassi2025-taxonomy-inefficiencies} extend the taxonomy to LLM code, finding redundant steps, duplication, and unnecessary conditionals most prevalent. Software aging~\citep{parnas1994-software-aging} and technical debt~\citep{cunningham1992-technical-debt} cause progressive structural degradation under modification~\citep{li2022-architecture-erosion, le2021-architectural-decay}. \citet{dou2024-whats-wrong-llm-code} show that LLM code is shorter in lines but has higher cyclomatic complexity, and \citet{cotroneo2025-human-vs-ai} find lower aggregate CC but more vulnerabilities. SlopCodeBench refines both: aggregate complexity may fall while \emph{concentration} worsens as branch logic accumulates in fewer functions.

\paragraph{Single-shot and from-scratch benchmarks.} \citet{swe-bench} established the dominant paradigm for repository-level evaluation, with extensions broadening language and domain coverage~\citep{swe-bench-plus, multi-swe-bench, rust-swe-bench, swe-rebench-v2, swe-polybench}. The test-passing frame has known fragility~\citep{swe-abs, lessleak-bench}. Instruction-following benchmarks evaluate compliance across conversation turns~\citep{codeif-bench, multicodeif} but assess each response independently. A second wave targets feature-level development from existing repositories~\citep{fea-bench, featurebench}. A third wave builds entire projects from scratch. \citet{commit0} generate libraries from specifications with interactive test feedback, several benchmarks construct full repositories from natural-language requirements~\citep{projdevbench, e2edevbench, nl2repo-bench, swe-agi, projecteval}, and \citet{longcli-bench} spans from-scratch construction through refactoring. Tasks grow larger and harder across all three waves, but evaluation in each case is a single artifact assessed against a fixed specification. The agent never revisits its own prior output.

\paragraph{Iterative and evolutionary benchmarks.} The closest prior work attempts iterative or evolutionary evaluation but removes or limits the feedback loop through which compounding accumulates. \citet{sr-eval} refine requirements stepwise and \citet{recode-h} incorporate interactive human feedback, but both evaluate each step independently. \citet{swe-ci} draws tasks from public repositories, creating contamination risk when frontier model training data likely includes both the repos and their commit histories. \citet{codeflowbench} formalize multi-turn code flow but supply gold-standard implementations for prior turns, so each turn starts from a clean state rather than the agent's own accumulated output. \citet{maintaincoder} apply single modifications with no chaining. \citet{humanevo} roll repositories back to earlier commits to create evolution-aware tasks but do not chain agent output across steps, so each task is still effectively single-shot. \citet{evoclaw} preserve agent code across 98 milestones spanning seven repositories; pass rates drop from 80\% in isolation to 38\% under continuity, and qualitative anti-patterns parallel structural erosion. Evaluation remains entirely pass/fail with no quantified quality trajectories. \citet{thai2025-swe-evo} frame long-horizon evolution, but each task is single-shot with no quality metrics. SLUMP~\citep{slump} is the closest analogue: roughly 60 progressively disclosed coding requests paired against a single-shot control, measuring faithfulness loss as specifications accumulate. The target of measurement, however, is semantic faithfulness to individual design commitments, not code-quality trajectories that track how verbosity and erosion evolve across checkpoints. SlopCodeBench is the only benchmark that chains agent output across checkpoints, uses synthetic specifications to eliminate contamination risk, and measures quality trajectories at every step.
